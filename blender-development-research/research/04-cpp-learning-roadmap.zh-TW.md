# C++ 3D 編輯器的實作學習路線

更新日期：2026 年 10 月 11 日。

這條路線以能完成的成果作為階段邊界。你已有基本程式能力，可以先執行核心範例，再做視窗與圖形，不必先讀完整個 Blender。各階段沒有保證工期；理解程度、投入時間與工具經驗會影響進度。

## 學習用技術組合

| 工具 | 用途 | 選擇理由與邊界 |
| --- | --- | --- |
| C++20 | 核心資料與操作 | 可練習明確所有權、容器、RAII 與編譯期型別。不是聲稱 Blender 全部使用同一標準。 |
| CMake 與 CTest | 建置、模組與測試 | 核心範例直接使用；先管理 target，再加其他依賴。 |
| Visual Studio 的桌面 C++ 工具 | Windows 編譯與除錯 | 適合目前桌面開發方向；範例也可用其他相容編譯器。 |
| SDL3 | 視窗、輸入與圖形 context | 讓初版把精力放在編輯器流程。 |
| Dear ImGui | 工具列、屬性與除錯介面 | 有 SDL3 與 OpenGL backend。中文輸入、無障礙與完整產品介面仍需評估。 |
| OpenGL 3.3 Core 起步 | 第一個 GPU viewport | 初期用來學 buffer、shader 與座標；後續依目標平台評估其他 API。 |
| GLM | 向量、矩陣與變換 | 借用數學實作，同時測試自己選定的座標約定。 |

上述是學習配置，不是對所有產品的最佳選型。Dear ImGui 官方提供 SDL3＋OpenGL 的整合範例；SDL 提醒 Windows 上較新的 OpenGL 函式需載入，也要求特定 context 操作在主執行緒執行。[ImGui 範例](https://github.com/ocornut/imgui/blob/master/examples/example_sdl3_opengl3/main.cpp)、[SDL context](https://wiki.libsdl.org/SDL3/SDL_GL_CreateContext)

你的 viewport 使用 OpenGL 函式時，要有自己的函式載入安排，不要假定 ImGui backend 內部的載入器已對整個應用程式提供 API。固定依賴版本或 commit，並記錄建置條件。若做正式商業工具，可再比較 Qt 等介面工具與適合平台的繪圖 API；這些不需要在第一個練習同時引入。

## 第零階段建立可以持續建置的程式

先編譯[核心範例](../examples/mini-editor-core/README.zh-TW.md)，跑 demo 和測試。用除錯器停在 `Document::execute()`，逐步觀察命令、候選場景、驗證、歷史及版本變動。

成果是你能解釋失敗命令為何不破壞現有場景。接著自行增加 `SetTranslation` 或 `RenameObject` 命令，並測試執行、Undo、Redo、保存再載入的一致性。

## 第一階段建立能觀察的圖形視窗

開啟視窗，處理關閉與 resize；先畫三角形，再畫座標軸與立方體。加入攝影機 orbit、pan、zoom。顯示邏輯視窗尺寸、framebuffer 尺寸、CPU 畫面時間與 GPU 資源數量。

完成條件是縮放、resize 或切換顯示縮放後，畫面不拉伸、滑鼠座標可以正確換算。此時必須能指出 vertex buffer、index buffer、shader、projection 和 view matrix 各自負責什麼。

## 第二階段用文件驅動畫面

把範例的 Scene 接到 viewport，讓兩個物件共用一份 GPU 網格。增加物件列表與屬性面板；介面只讀取當下資料，所有修改送到命令層。

完成條件是移動 Cube A 時，Cube B 的位置不變，GPU 網格也不重複建立。主視窗關閉前，GPU 資源依正確順序釋放。再用不開 GUI 的測試確認場景操作仍可執行。

## 第三階段做選取與一次完整拖曳

先用 CPU 射線選取物件，選中的項目用外框或顏色顯示。做單軸移動 gizmo，加入數字輸入、確認與 Esc 取消。

拖曳 200 次滑鼠事件，確認後只留下 1 筆 Undo。取消時位置回復，沒有多出歷史。屬性面板、選單與 gizmo 的移動最後呼叫相同核心邏輯。

注意 ImGui 是否取得滑鼠或鍵盤輸入：在數字欄位輸入時，不能同時把按鍵送給 viewport 快捷鍵。官方整合文件說明輸入捕捉的處理。[ImGui 整合指南](https://github.com/ocornut/imgui/wiki/Getting-Started)

## 第四階段把檔案讀寫變成可靠流程

先接核心範例的有版本文字格式，加入開啟、另存與未保存標記。讀檔先驗證再替換；檔案寫入改成暫存及替換原檔的流程。

建立測試資料：空場景、兩個實例、含 Unicode 的名稱、截斷檔案、重複 ID、非法索引，以及不支援的版本。舊版本測試檔保留在版本控制中。

完成條件是讀壞檔後原場景仍能操作；保存失敗不會把原檔變成半份新檔。這一階段也要決定載入是否清空歷史、目前選取如何恢復、崩潰復原檔如何識別。

## 第五階段加入第一個網格編輯工具

先做面選取，再做單面擠出。分開原始網格、編輯拓樸與繪製三角形。建立邊與面鄰接，決定是否只支援流形輸入。

完成條件是擠出、取消、Undo、保存再開啟都保持正確拓樸；UV 等角落資料有明確的繼承規則。這時再讀 BMesh，比直接鑽研所有建模操作容易理解。[BMesh](https://developer.blender.org/docs/features/objects/mesh/bmesh/)

## 第六階段做修改器與增量更新

加入第一個非破壞式修改器，例如簡單的頂點偏移或 Mirror。作者網格保留，求值結果另外生成。接著加入父子變換，標記 dirty 並依順序求值。

完成條件是變更物件位置不重新建立未改變的網格；改網格時所有實例都更新。測試插入父子循環會被拒絕，以及 Undo 後的快取沒有殘留新結果。

## 第七階段做時間與動畫

先對位置做關鍵影格，以線性插值求值；再加入旋轉四元數、曲線插值和播放控制。渲染器讀取指定時間的求值結果，不把它寫回作者的固定屬性。

測試同一時間求值結果一致、跳轉時間與連續播放得到相同結果，以及修改曲線後相關快取失效。骨架、蒙皮、IK 與物理模擬會帶來更多相依和時間狀態，可在掌握這個流程後逐項加入。

## 第八階段做匯入與背景工作

先針對 glTF 的一個有限子集實作或整合匯入，明列支援內容，例如靜態網格、階層和基礎材質。轉換到自己的資料庫，再由同樣的不變條件驗證。[glTF 規格](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)

讓重工作讀取快照並回傳結果。測試使用者匯入途中關閉文件、取消，或再次匯入另一個資產。舊結果必須依文件身份和版本被拒絕，不能在回呼中直接碰已釋放的 UI。

## 第九階段建立可擴充的操作與屬性

把命令註冊成名稱與參數描述，從選單、快捷鍵及測試呼叫。先為目前已有操作設計 API，再提供腳本或外掛。

完成條件是新增工具不需要修改所有面板；外掛能查詢版本與支援能力，核心不把內部記憶體布局當作長期契約。先實作「腳本建兩個物件並移動其中一個」，再評估跨 DLL ABI。

## 第十階段選定一個可交付的專業用途

選一項實際任務，例如簡單商品展示圖、低多邊形資產編輯或特定程序化模型。邀請使用者用它做完整作品，記錄無法完成的步驟、錯誤及耗時。

在已有用途的基礎上加材質、燈光、動畫或輸出。若選寫實渲染方向，再獨立學 ray、BVH、取樣、材質與 path tracing。PBRT 提供連結演算法與實作的教材，但整個編輯器不必等待你寫完路徑追蹤器。[PBRT 第四版](https://pbr-book.org/4ed/)

## 每完成一個階段留下四種記錄

| 記錄 | 例子 |
| --- | --- |
| 可重現的建置與測試 | 編譯器、依賴版本、命令與測試結果。 |
| 一頁設計說明 | 資料由誰擁有、誰能修改、失敗如何處理。 |
| 一個真實使用情境 | 用自己的軟體完成一個小場景或資產。 |
| 下一步瓶頸 | 哪個量測或使用問題要求新增功能或重構。 |

你學到的架構會隨成果成長：從一個 revision 到局部 dirty，從快照 Undo 到差異歷史，從三角形陣列到可編輯拓樸。每次重構都有具體問題和回歸案例可檢查，這正是大型軟體逐步建立的方式。
