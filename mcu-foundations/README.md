# MCU 跨平台學習課程

這個課程給有軟體開發經驗、從零接觸微控制器的學習者。目標是看到陌生 MCU 時，能理解架構、查找文件、建立可除錯的程式，並判斷它是否適合需求。你不需要記住所有品牌、產品線或 SDK。

學習的單位是「問題與機制」：資料從哪裡來、誰搬資料、誰決定執行時機、記憶體由誰擁有，以及失敗時如何觀察。廠牌名稱只是這些機制的一種實作。

## 從這裡開始

1. 讀 [共通架構與軟體堆疊](01-mental-model.md)，建立分類方式。
2. 做 [第一課](lessons/00-first-principles.md)，今天不用開發板也能開始。
3. 按 [實作路線](02-learning-path.md) 推進，每一關都有可觀察的驗收條件。
4. 選板前讀 [選型與文件閱讀](03-selection-and-documents.md)。已有板子就先評估能否沿用。
5. 用 [學習紀錄](learning-log.md) 留下預測、證據與錯誤，而不只是抄程式。

## 課程主線

用同一個「資料採集器」逐步學習：定時取得資料、緩衝、透過 UART 傳送、接受設定命令、處理斷線與重啟。前期用人工產生的資料，之後再接 ADC 或感測器。完成後換另一個平台移植，檢驗哪些知識可以帶走。

先用單核心、無作業系統的流程看清資料與時間，再加入中斷、DMA 和 RTOS。Cortex-M 可作為第一個具體學習架構，但 MCU 不等於 Cortex-M；第二平台可以比較另一廠商的同類核心，也可以進一步比較 RISC-V。

## 何時算學會

- 能從 reset 說明程式如何走到 main，並找到相關原始碼。
- 能說明一個周邊所需的時脈、接腳、暫存器和事件通知。
- 能用量測和 debugger 區分硬體設定、驅動程式與應用邏輯的錯誤。
- 能計算資料率、緩衝區和時間預算，並解釋超載時的行為。
- 能移植應用核心，指出必須改動的硬體與 SDK 邊界。
- 能依需求縮小 SKU 範圍，而不是從產品型錄第一頁開始讀。

## 範圍與節奏

先採每週 4 至 6 小時、約 12 至 16 週的規劃估算；以驗收通過為進度，不以週數保證熟練。第一輪暫緩圖形介面、USB 協定細節、無線協定、馬達控制、多核心與自製 PCB；有需求時再沿著已學會的架構擴充。

本目錄獨立於既有 HMI 研究，以一般 MCU 能力為範圍。所有品牌使用相同的比較與查證標準。官方文件入口見 [參考資料](references.md)。
