# MCU 選型與文件閱讀

## 先縮小需求再看產品線

先寫出硬限制，再找候選系列，最後挑完整料號和封裝。初學選板時，建置、除錯與文件的完整度，比追求最高規格更有教學價值。這裡先提供篩選方法；具體購買型號應在確認手上硬體、預算及當時供貨後決定。

| 需求 | 轉成可檢查的條件 |
| --- | --- |
| 連接哪些裝置 | 介面實例數、接腳複用、電壓、外部收發器需求 |
| 每秒多少資料 | 來源速率、有效通訊速率、CPU 處理量、DMA 能力 |
| 允許多少延遲 | 最長中斷阻塞、最差處理時間、排程與通訊延遲 |
| 要留多少資料 | 靜態資料、stack、heap、buffer、middleware 和餘裕 |
| 如何供電 | 工作與休眠比例、喚醒來源、板上耗電及供電限制 |
| 如何維護 | 除錯介面、故障紀錄、更新方式、SDK 維護與授權 |
| 如何量產 | 封裝、溫度範圍、供貨、生命週期、單價與測試成本 |

先把必須滿足的條件用來淘汰，再比較性能和成本。學習用板與量產晶片的最優解可能不同。

## 第一塊板的檢查表

- 有清楚的電路圖、板子使用手冊，以及精確的晶片料號。
- 有可用的硬體除錯途徑；板載 debugger 或已確認相容的外接 probe。
- 有 LED、按鈕、可引出的 UART，以及後續實驗需要的 timer 和介面。
- 官方基礎範例能在你的作業系統及工具鏈上建置。
- 能取得 reference manual、datasheet 和 errata。

已有板子時先跑階段 1，不急著再買。尚無板子可以先做第一課與桌機端協定練習，但電氣訊號、真實中斷延遲與功耗仍需硬體驗證。

## 文件不是從第一頁讀到最後一頁

| 文件 | 遇到什麼問題才打開 |
| --- | --- |
| Datasheet | 這個完整料號和封裝有什麼、電壓與時序限制是多少 |
| Reference manual | 周邊如何設定、旗標如何清除、先後順序是什麼 |
| Core manual | CPU 例外、指令、核心暫存器與記憶體模型如何工作 |
| Errata | 是否有已知硬體限制，是否適用這個晶片版本 |
| 板子電路圖與手冊 | LED 接哪裡、哪個 USB 連到 debugger、跳線如何設定 |
| SDK 文件與原始碼 | 函式是阻塞還是非阻塞，callback 何時執行，buffer 要存活多久 |
| Application note | 某項設計的實作範例與建議條件；仍需確認適用型號 |

名稱因廠商而異，有些文件會合併。讀文件時記下版本、章節與適用料號，避免拿同系列另一顆晶片的限制來套用。

## 讓陌生平台在一小時內變得可分類

這是一個練習目標，不要求一小時內就能完整移植。

1. 找到核心、Flash 和 SRAM 配置，以及 boot 與 debug 入口。
2. 找到板上的 LED 接腳、有效電位與所需時脈。
3. 找到 blink 專案，辨認 startup、linker、BSP、driver 和應用檔案。
4. 追一個 GPIO 呼叫，直到能對上手冊中的硬體動作。
5. 列出還不能確定的三件事，以及應該去哪份文件查。

Zephyr 的 board porting 文件可用來觀察另一種板級描述方式；其板級資料包含板上元件與接腳配置。先理解 BSP 的問題，再讀這種具體實作，會比較容易掌握。[Zephyr Board Porting Guide](https://docs.zephyrproject.org/latest/hardware/porting/board_porting.html)
