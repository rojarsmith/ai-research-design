# 軟體平台支付整合研究

研究日期：2026-10-12（Asia/Taipei）。

研究不同軟體平台如何串接收款服務、支援各種支付方式，以及處理訂單、訂閱、退款與對帳。目前使用者已有 Stripe，第一階段先收錄 Stripe 測試卡資料，再逐步比較其他收款服務。已有帳戶是研究起點，不代表預設 Stripe 適合所有平台。

## 已收錄資料

- [Stripe 測試信用卡與驗收情境](research/01-stripe-test-cards.zh-TW.md)：彙整指定的 Karbon 文章，列出官方核對後的卡號、錯誤碼、原文修正及測試清單。
- [英文概要](research/01-stripe-test-cards.md)：來源、範圍與完整繁體中文資料入口。

## 軟體平台的初步整合方向

以下是研究起始架構；具體平台、外掛版本與支付方式支援仍須逐項查核。

| 平台類型 | 初步整合方向 | 後續研究重點 |
| --- | --- | --- |
| 自製網站與 Web SaaS | Stripe Checkout 提供託管或嵌入式付款頁；Elements 可用於自訂介面。[官方文件](https://docs.stripe.com/payments/checkout) | 單次收款、訂閱、前後端責任、Webhook 與會員權限同步 |
| iOS、Android 與 React Native | Stripe 提供行動支付 SDK 與 Payment Sheet。[官方文件](https://docs.stripe.com/payments/mobile) | 商品類型、商店規則與銷售地區、驗證後返回 App、錢包支付 |
| 桌面軟體 | 候選設計：後端建立付款頁，系統瀏覽器完成付款，軟體向後端查詢授權 | Windows、macOS、Linux 的返回流程、登入綁定與授權更新 |
| 電商與內容管理平台 | 待查：WooCommerce、Shopify 等平台的原生支付、官方外掛與第三方外掛 | 是否能使用現有 Stripe 帳戶、版本、地區限制、退款和訂單狀態同步 |
| 無程式碼平台 | 待查：內建收款元件、支付連結或自訂 API | 平台費用、Webhook 能力、資料匯出、訂閱管理 |
| 多商家市集 | Stripe Connect 用於多帳戶與商家間的金流。[官方文件](https://docs.stripe.com/connect) | 商家驗證、拆帳、撥款、退款責任、可支援的國家 |

行動 SDK 的技術支援不等於所有數位商品都可使用外部支付；必須依實際商品、地區與當時的商店規則研究。桌面付款流程是候選架構，尚未實作驗證。

## 支付服務與支付方式的比較框架

「軟體平台」是整合的產品環境；「支付服務」是收款供應商；「支付方式」是消費者實際使用的信用卡、電子錢包、銀行轉帳等。三者分開記錄，才能看出同一供應商在不同平台與國家的限制。

後續候選收款服務包含 Stripe、PayPal、Adyen，以及台灣在地服務如綠界、藍新；目前尚未完成供應商比較。每項都用相同欄位查證，不因既有帳戶或公司立場預設優劣。

| 比較面向 | 要記錄的問題 |
| --- | --- |
| 商家與市場 | 商家註冊國家、收款主體、客戶市場、結算銀行與幣別 |
| 支付方式 | 信用卡、Apple Pay、Google Pay、銀行轉帳及各地支付的實際可用條件 |
| 整合能力 | 託管頁、SDK、API、平台外掛、Sandbox 與維護狀態 |
| 商業模式 | 單次付款、訂閱、用量計費、儲值額度、多商家拆帳 |
| 訂單與帳務 | Webhook、重複通知、付款延遲、退款、爭議款、對帳與服務權限 |
| 成本與責任 | 交易費、外匯費、平台加收費、退款費、拒付成本及稅務責任 |

## 下一階段研究順序

1. 確認第一個要串接的軟體平台、單次或訂閱模式，以及 Stripe 帳戶國家。
2. 查核該平台的 Stripe 整合方式及可用支付方式，整理設定步驟和驗收情境。
3. 以相同商家、客戶市場和交易條件比較第二家支付服務。

目前交付研究資料，尚未連接 Stripe 帳戶、建立交易或執行付款測試。
