## Claude 已如何被產品使用

本機 `server/assistant/openrouter.ts` 的 `OPENROUTER_BASE` 指向 `https://openrouter.ai/api/v1`，預設模型識別為 `anthropic/claude-fable-5`。`server/assistant/keyStore.ts` 將 provider 定義為 `openrouter` 與 `ollama`。產品網站的說明與這兩個選項一致。

因此適合的寫法是：「產品的雲端 AI 助理目前透過 OpenRouter 使用 Claude，另提供 Ollama 本機模型選項。」本次所查文件與 provider 模組未顯示第一方 Anthropic provider；不要把現在的使用寫成直接 Claude API 串接或公司已有 Console 消費。

申請可以說明已使用 Claude 模型與後續評測需求；公開資料沒有證明必須完全排除其他模型才合格。原本的模型選擇設計應按產品需要決定，不必為申請刪除 Ollama 或其他模型。

### 使用 Console 額度的工程提案

以下是後續建議，尚未實作，也不是官方申請要求：

1. 先以第一方 API 寫獨立評測工具，使用去識別的範例專案，驗證模型讀圖與工具呼叫。
2. 若測試證明有產品價值，再新增 `anthropic` provider，沿用既有編輯器動作、驗證與復原方式。
3. 重新處理訊息／工具格式、串流、錯誤、模型選單及成本顯示；不能只換 OpenRouter URL 或模型名稱。
4. API key 維持在本機橋接層或合適的後端。公司實驗與未來客戶使用的組織、成本與金鑰分開規劃。

公司 Console 額度適合自有評測和授權的產品實驗，不應宣稱已提供所有客戶永久免費 API。額度轉售／轉移另受[官方 Credit Terms](https://www.anthropic.com/legal/credit-terms)限制。

## 送件前應修正的資訊矛盾

本機 `README.zh-TW.md` 目前同時有 `Production Ready`、MIT 標示與 `0.9.0-dev`；公開網站仍為 `0.8.5 Alpha`。`installer/licence/README.md` 則將產品描述為免費散布的專有閉源軟體，`EULA.txt` 記載 EDT 授權及硬體用途條件。授權說明仍是草稿，不能僅憑 README 的徽章認定產品開源。

這些矛盾會使審核者難以判斷產品階段和經營方式。準備申請時：

- 以實際對外可取得版本說明階段，將本機開發版與公開 Alpha 分開。
- 確認產品真正的授權與商業模式，修正提供給審核者的資料。
- 若軟體免費、商業收入主要來自硬體或服務，就如實說明；不要寫成已有付費 SaaS。
- 若仍由 EDT 經營，保留公司關係的透明敘述。新公司的成立資料只有在新公司實際存在並經營產品時才適用。

研究只记錄矛盾，未修改原專案或公開網站。

## 最值得準備的評測與業務證據

以下是一個可執行的申請補強方案，不是已取得的成果：

| 材料 | 建議做法 | 留下的證據 |
| --- | --- | --- |
| 三分鐘產品展示 | 描述／草圖 → 生成畫面 → 修改文字或圖示 → 一步復原 → 預覽；設備傳送維持人工決定 | 一個連結、使用版本、示範日期 |
| 兩個代表案例 | 咖啡機和洗衣機使用相同評估步驟 | 範例輸入、結果、人工修改紀錄 |
| 小型模型評測 | 選 20 個代表任務，記錄合法工具操作、生成結果、失敗及重試 | 模型／日期、成功定義、原始記錄 |
| 真實試用進展 | 記錄實際受測團隊、問題與回饋；未取得同意的客戶名稱不對外使用 | 經授權可提交的摘要 |
| API 預算 | 從每任務輸入／輸出 token、重試與單價估算 | 每任務成本和預計每月任務量 |

例如「20 個任務中完成 16 個」只有實測完成後才能出現在申請。示範片可以證明有工作流程；成效百分比需要測量基準，不能從影片推導。
