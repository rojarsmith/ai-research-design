# 實作建置計畫

這是一條實作路線，而非背誦主題清單。每個階段都為渲染器加上一項能力，產生可觀察的結果，並在實驗筆記中解釋它。目前已完成實驗 01；其餘階段是之後逐步完成的練習。

## 00 — 建立像素工作區

**製作：** CPU 色彩緩衝區，以及將其顯示在瀏覽器 canvas 的方法。

**需要時再學：** 整數與浮點座標、影像列與欄、RGB／RGBA、正規化座標與像素座標。

**檢核：** 說明 `(x, y)` 如何對應到陣列索引，以及影像列順序為何重要。附上的三角形實驗已使用這項基礎。

## 01 — 填滿三角形（已實作）

**製作：** 用邊函數判斷三角形涵蓋範圍，並插值頂點顏色。

**需要時再學：** 2D 外積、有向面積、重心座標、像素中心取樣、浮點容差。

**檢核：** 解釋頂點繞序、退化三角形，以及共用邊為何需要一致的填充規則。完成 `labs/01-triangle/README.md` 的 A–F 題。

## 02 — 加上 2D 變換與線框除錯

**製作：** 由多個變換三角形組成的小場景，加上平移、旋轉、縮放控制、頂點標記和邊線除錯覆層。

**需要時再學：** 行向量與列向量、矩陣相乘順序、齊次座標、座標系手性。

**檢核：** 預測以相反順序套用兩個變換的結果，並在程式中區分世界座標與像素座標。

## 03 — 產生第一張 3D 畫面

**製作：** 由三角形組成旋轉立方體、環繞攝影機與透視投影；先畫線框，再畫填滿的面。

**需要時再學：** 模型／世界／視圖／裁切空間、攝影機基底、視角、近遠裁切面、透視除法、視口映射。

**檢核：** 追蹤一個頂點經過各座標空間，解釋距離較遠的物體為何顯得較小。畫出視錐，標出程式採用的裁切體慣例。

## 04 — 判斷哪些表面可見

**製作：** 加上深度緩衝區、背面剔除，以及近裁切面的裁切；提供開關比較每項功能。

**需要時再學：** 深度測試、三角形繞序、齊次裁切、深度衝突、深度精度。

**檢核：** 用交疊網格解釋為何繪製順序排序會失敗，而逐樣本深度測試能處理。再說明仍會造成深度衝突的情境。

## 05 — 將幾何交給 GPU

**製作：** 先把相同立方體移植到 WebGL 2。上傳位置與索引，撰寫頂點和片段著色器，再讓矩陣動起來。接著可沿 NVIDIA 路線加入原生 OpenGL 4.6 版本，在 GeForce 上執行。

**需要時再學：** 圖形環境、頂點緩衝區、頂點屬性、uniform、著色器編譯、頂點間插值。

**檢核：** 說明哪些運算每個頂點執行、哪些運算每個涵蓋取樣點執行。用相同頂點資料與變換比較 CPU 和 GPU 結果。

## 06 — 加入材質、光照與貼圖

**製作：** 逐頂點或逐片段 Lambert 漫反射、Blinn–Phong 高光、法線與取樣貼圖。

**需要時再學：** 法線變換、內積、光線方向、UV 座標、貼圖濾波、螢幕 sRGB 與線性光計算。

**檢核：** 獨立旋轉物體和光源。解釋非均勻縮放下法線為何不能照搬位置的變換，以及在錯誤色彩空間混色為何看起來較暗。

## 07 — 陰影與影像品質

**製作：** 雙階段陰影貼圖，並比較簡單抗鋸齒方法。保留陰影偏移與解析度控制。

**需要時再學：** 繪製至貼圖、光源空間變換、混疊、PCF 濾波、偏移瑕疵、成本與品質。

**檢核：** 擷取一張陰影痤瘡和一張陰影分離的瑕疵；調整偏移並記錄取捨。以相同縮放比例比較鋸齒與濾波邊緣。

## 08 — 期末專題：迷你渲染器展示

**製作：** 可移動攝影機的場景，至少含兩個網格、深度、一個有貼圖的光照材質，以及陰影或明確記錄的替代方案。另附功能開關或除錯檢視。

**交付：** 原始碼、簡短錄影或截圖，以及 1–2 頁設計說明。追蹤一個頂點如何到達顯示的片段，列出座標與深度慣例，描述一個自己診斷的錯誤，並說明一項畫質／效能取捨。

**自我檢視：** 同學應能執行場景、改變一個控制項，並看懂渲染流程圖，不必讀完所有原始碼。

## NVIDIA GPU 路線 — RTX 5070 Ti

CPU 三角形實驗仍是對照版本。進入 GPU 階段後，先用 WebGL 2 快速開始，再加上原生 C++／OpenGL 4.6 應用程式，讓 NVIDIA 圖形工具能檢視自己渲染的影格。這張 GPU 支援 OpenGL 4.6 與 Vulkan 1.4；NVIDIA 目前的 Nsight Graphics 需求列有 RTX 50 系列，並支援 OpenGL 與 Vulkan。安裝前請查看 [RTX 5070 系列規格](https://www.nvidia.com/zh-tw/geforce/graphics-cards/50-series/rtx-5070-family/)和 [Nsight Graphics 系統需求](https://developer.nvidia.com/nsight-graphics/get-started)。

**實作順序：**

1. 確認應用程式確實使用 RTX 5070 Ti，記下驅動與圖形 API 資訊。
2. 用 Nsight Graphics 擷取單一影格。檢查繪製呼叫、頂點輸入、著色器階段、貼圖、目標緩衝區與深度狀態。
3. 修改一個著色器或資源，再擷取一次。解釋變更如何反映在影格上，以及是否影響畫質或影格時間。
4. 用 GPU trace 或著色器分析器比較一個簡單工作負載和一個較重的工作負載。將擷取資料當成證據，而不是整顆晶片的完整模型。
5. **選修運算橋接：** 撰寫 CUDA 影像濾鏡，並和片段著色器版本比較。藉此學習執行緒執行與記憶體搬運；CUDA 是通用 GPU 運算，不能取代圖形管線。
6. **進階選修：** 理解一般深度、材質與陰影後，再以 Vulkan 加入光線查詢或光線追蹤陰影。

Nsight 可用功能會依版本、API、驅動和 GPU 而異。先在概念上保持渲染器 API 中立；使用 NVIDIA 專屬擷取工具時，則用來診斷這張 GeForce 的實際行為。

## 硬體主線 — 了解工作實際跑在哪裡

搭配上方各階段逐步學習。目標是能解釋 GPU 的執行與記憶體模型如何影響畫面效能，不是背誦某家廠商的晶片方塊圖，也不必先學電路設計。

- **對應渲染管線（階段 03–05）：** 分辨可程式化著色器工作，以及圖元組裝、光柵化、深度／模板測試、混色與貼圖取樣等管線階段。把可見功能對應到產生它的階段。
- **平行執行（階段 05–06）：** 了解大量頂點或片段為何能平行執行；學習 SIMD／SIMT、執行群組、隱藏延遲與分支發散。群組寬度與排程的精確細節依硬體而異。
- **記憶體與資料搬運（階段 05–07）：** 分辨暫存器、快取、貼圖取樣、顯示記憶體容量／頻寬，以及 CPU↔GPU 上傳與讀回。預測場景何時受算術、記憶體流量、資料搬運或同步限制。
- **像素與顯示路徑（階段 01、04、07）：** 將影格格式、深度精度、混色與色彩空間連到儲存和輸出；概略了解渲染影格如何送到顯示器。更新率和掃描輸出細節初期可選修。
- **先量測再最佳化（階段 07–08）：** 分別改變解析度、過度繪製、著色器運算量、網格數與貼圖大小，觀察影格時間。先提出瓶頸假設，再用瀏覽器／GPU 分析工具或控制變因的比較驗證。硬體計數器與廠商工具屬於延伸內容。

**硬體檢核：** 畫出渲染管線並標出可程式化工作；解釋 GPU 為何偏好大量平行工作，而非單執行緒快速回應；各舉一個受頻寬與受運算量限制的場景；以證據指出一個瓶頸及一項改善影格時間的修改。不要只憑使用率百分比推定瓶頸。

## 建議的學習節奏

每個階段可以拆成短循環：

1. **預測：** 修改程式前先畫圖，或寫下預期數值。
2. **實作：** 每次加一項能力，保留可比較的已知正常版本。
3. **觀察：** 用控制項、除錯顏色或刻意破壞的案例顯示行為。
4. **解釋：** 記錄發生什麼、原因、前提與反例。

資工背景所學的數學可派上用場，但不必為了完整複習數學而停下專案。等渲染器需要時再推導小片段：用外積與內積處理幾何和光照，以矩陣轉換座標，用插值傳遞屬性，用取樣處理像素與貼圖。
